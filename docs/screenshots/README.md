# How the screenshots were made

The `docs/images/real-*.png` screenshots come from the real desktop app on Linux, playing live
(synthetic) video from a local go2rtc. No real camera, address or account is in them: the
streams are generated by FFmpeg, and go2rtc is reached at the documentation address
`192.0.2.10` (RFC 5737), added to the loopback interface.

| File | Shows |
| --- | --- |
| `real-grid.png` | The camera wall: view "Home", 8x4 cells, a portrait doorbell tile next to 16:9 and 4:3 tiles, all live over WebRTC |
| `real-fullscreen.png` | One camera in fullscreen with its top bar and the shortcut hint |
| `real-settings.png` | Settings: views, backup, cameras |
| `real-settings-about.png` | Settings scrolled down: the camera list and the About section |
| `real-view-editor.png` | The view editor with the "Home" view and the first tile selected |
| `real-import.png` | Import from go2rtc after "Fetch streams", WebRTC selected, two new streams |
| `real-licenses.png` | Open-source licenses |

## Steps

Needs: JDK 21, Xvfb, xdotool, ImageMagick (`import`), FFmpeg with libx264, pngquant and optipng,
and go2rtc (v1.9.14, `go2rtc_linux_amd64` from its GitHub releases), all outside the repository.

```sh
SCRATCH=$(mktemp -d)

# 1. The documentation address on loopback, so the app can show 192.0.2.10 and still play.
sudo ip addr add 192.0.2.10/32 dev lo

# 2. go2rtc with six synthetic cameras (front_door, driveway, garden, garage, doorbell 9:16,
#    backyard): FFmpeg lavfi sources (gradients, life, cellauto) with a camera-style timestamp,
#    published to go2rtc over RTSP.
docs/screenshots/streams.sh /path/to/go2rtc "$SCRATCH/streams"

# Two extra streams so the import screen has something new to offer:
for n in side_gate side_gate_sub carport; do
  curl -X PUT "http://127.0.0.1:1984/api/streams?name=$n&src=rtsp://127.0.0.1:8554/garden"
done

# 3. Build the app image.
./gradlew -Pcamgrid.skipAndroid=true :desktop:createDistributable

# 4. A virtual 1280x720 screen and a window that fills it (no window manager, so no title bar).
Xvfb :99 -screen 0 1280x720x24 -nolisten tcp &
mkdir -p "$SCRATCH/data"
printf 'width=1280\nheight=720\nx=0\ny=0\nplacement=Floating\n' > "$SCRATCH/data/window.properties"

# 5. Start the app with its own data directory.
DISPLAY=:99 SKIKO_RENDER_API=SOFTWARE CAMGRID_DATA_DIR="$SCRATCH/data" \
  desktop/build/compose/binaries/main/app/CamGrid/bin/CamGrid &
```

The config (`demo-config.json` here) has to go in through the app, because the config file is
encrypted. Either import it in the app (Settings > Backup > import accepts a bare config file),
or, as was done for these screenshots, write it with the app's own store from a scratch JUnit
test in `desktop/src/test` that is not committed:

```kotlin
val dir = Path.of(System.getenv("SHOTS_DATA_DIR"))
DesktopConfigStore(dir, KeyVaults.forThisOs(dir)).write(File("docs/screenshots/demo-config.json").readText())
```

Then drive the window with xdotool (clicks on the settings button, Done, a tile, the Escape key,
the scroll wheel with `click 5`) and capture it:

```sh
DISPLAY=:99 import -window root shot.png
pngquant --quality 0-90 --speed 1 --strip --ext .png 256 shot.png   # video screenshots
optipng -o2 shot.png
```

Each image is the whole 1280x720 window. Video screenshots are taken about 15 to 20 seconds after
the streams start; earlier frames may still show "Connecting..." or decoding artefacts.
